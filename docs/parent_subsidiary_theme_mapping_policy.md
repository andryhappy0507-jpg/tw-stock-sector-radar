# Parent / Subsidiary Theme Mapping Policy

## Purpose

子公司、關係企業或集團公司具備某項 Theme，不代表上市母公司股票可以自動繼承該 Theme。本政策用於判斷 Theme 關聯是否能合理歸屬到可交易的上市公司，並避免以模糊的「集團概念股」擴張正式股池。

## Default rule

- 子公司證據預設只支持子公司本身，不自動向母公司、兄弟公司或整個集團傳播。
- 僅有持股、董事重疊、品牌相近或「集團旗下」稱呼，不足以建立上市母公司的正式 mapping。
- 被投資公司若只是被動財務投資，或 Theme 業務不受上市公司控制且未反映在其營運，維持 discovery / pending。

## Parent attribution gate

上市母公司至少同時符合以下兩類條件，才可進入人工審核：

1. **控制或明確關係**：年報、財報、MOPS、母公司官網或被投資公司官方資料能確認母子公司、合併個體、受控制事業或明確集團關係。
2. **母公司層級的實質曝險**：至少一項母公司官方或監管證據顯示該 Theme 是母公司的策略、資源投入、產品整合、製造部署、客戶交付、營收／損益貢獻或可辨識新事業，而非只有子公司單獨活動。

符合門檻後仍須記錄：

- `evidence_owner`：證據直接描述母公司、子公司或兩者。
- `relationship_type`：subsidiary / controlled_entity / affiliate / investment。
- `attribution_basis`：策略、資源、營運、部署、收入或其他歸屬理由。
- 子公司名稱與來源，以及母公司層級的獨立來源。

## Role ceiling

- 若 Theme 主要由子公司執行，而母公司證據只有策略、資源或場域整合，母公司原則上最高標示為 `related`。
- 只有在母公司自身形成主要產品／服務、可辨識事業線或重大營運來源時，才可標示為 `core`。
- 已有實質投入但商業化仍早期，標示為 `emerging`。

## Breadth and double counting

- Theme breadth 以可交易 `stock_id` 去重；同一上市股票旗下多家子公司不得重複增加家數。
- 若母公司與子公司皆為獨立上市股票，兩者必須各自通過證據與人工審核，不能互相繼承。
- Theme 頁面可顯示母子公司脈絡，但分析輸入仍保留各 Stock→Theme mapping 的角色與歸屬依據。

## Example: 2392 正崴 / 星科國際

星科的機器人產品不能只因「正崴集團旗下」就自動映射至 2392。正崴官網另明確說明星科運用集團算力、精密製造、通路及子公司場域進行驗證，且機器人方案屬集團智慧製造布局，因此達到進入人工審核的母公司層級門檻。由於執行主體仍是星科，建議 2392 的角色上限為 `related`；在使用者核准前不得寫入正式 mapping。
